Pint War Memories

Implementation and verification report · 6 October 2026

Implemented in source. Native iPhone verification remains outstanding.
No publishing or production build was performed. The browser cannot run the native exporter.

1. What already existed

  • The completed-war Memories route, completed-war summary, full-war Memories API feed and protected private-photo stream.
  • The existing weighted photo selection: temporal coverage, extra final-hours coverage, player/pub variety, duplicate avoidance and randomized fallback order.
  • Pinned FFmpegKit Next iOS build tooling and a downloadable verified artifact. At the start, no local module or vendored frameworks were present in the app, and the existing presentation was a slideshow rather than a generated MP4.

2. What was added

  • An Apple-only local Expo module under modules/pint-wars-memories, with a CocoaPods specification, privacy declaration and eight original device-arm64 XCFrameworks. FFmpegKit Next 9.0.0 source commit 5e51b2da4c3593c0f2f9b49f53eeb497d93e39d3. VideoToolbox enabled; GPL/x264 disabled. Original provenance and notices preserved.
  • The filesystem bridge uses the existing authenticated Blob endpoint. Native staging decodes/downsamples/orients each private photograph, composites its actual player/pub captions and writes a protected, job-owned portrait JPEG. No public or signed Supabase source URL is exposed.
  • A 720×1280, 30fps, 900-frame portrait H.264/AAC MP4: two-second opening, 25 seconds of existing selected photographs, three-second real winner/results card. Serial segments limit memory use; fades through navy provide timed transitions. AAC audio is silent; no music or cloud renderer was added.
  • Job-scoped cancellation and cleanup. Failures/cancellation release the job. Successful MP4 and selected thumbnail files stay while needed by the screen; player, Photos and share operations retain consumer holds so leaving the screen cannot delete an in-use file. Stale crash leftovers are pruned after 24 hours on the next generation.
  • Native AVPlayer playback, pause/replay, timeline and thumbnail seeking. The screen has the approved navy/gold structure, actual completed-war metadata, selected thumbnails, winner and final scores, generating/progress/error/retry states and real Save/Share controls.
  • Add-only Photos authorization and save completion/error handling. Permission denial provides a Settings action. Native sharing passes the local MP4 URL—not a public URL—to UIActivityViewController, and distinguishes completion, dismissal and failure.
  • Truthful unavailable states in web, Android and iPhone builds without the module. Save/Share are disabled when no actual generated film exists.
  • Generated-native-project ignore rules are anchored to the app root, preserving maintained local-module Swift source and vendored frameworks for version control/build uploads. The native verifier checks source inclusion explicitly.

No changes were made to the selection algorithm, protected API implementation, scoring, league mechanics, authentication, RevenueCat/payments, database schema, Map, Passport or unrelated screens. No new runtime package dependencies or external renderer were introduced. Expo/CNG is retained, with no generated ios/ or android/ directory committed.

4. Native-only verification still required

These frameworks contain device arm64 only, no simulator slice. Expo Go and browser playback are not substitutes. Linux cannot verify Swift compilation or native linking/embedding.

  1. Compile the generated iOS project on macOS, install on a real iPhone, and verify all eight dynamic frameworks are embedded and signed and the module loads.
  2. Generate from a real completed war's protected photos, including HEIC/orientation and missing-photo fallback; verify the resulting MP4 duration, portrait geometry, H.264 video/AAC audio, transitions and real final result.
  3. Exercise playback, replay, timeline and thumbnail seeking.
  4. Exercise Photos add-only allow/deny/restricted permissions, Settings return, save success and storage/save failures.
  5. Verify the share sheet receives the MP4 file and handles completion, dismissal, failures and leaving the screen while sharing/saving.
  6. Verify cancellation, back navigation, retry, encode/download failure and safe temporary-file deletion on device.

Until this pass, the feature must not be described as native-device verified or ready for release. Included LGPL/source notices do not by themselves establish all distribution/patent obligations.
